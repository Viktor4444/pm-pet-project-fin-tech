# Стейкхолдеры и RACI — Credit Journey

**Версия:** 1.0  
**Дата:** 2026-11-09  
**Согласовано:** Продуктовый отдел (бизнес-заказчик)  
**Подготовил:** PM / BA  

**Опора:** [One-pager](one-pager.md)  
**Назначение:** карта подразделений, матрица RACI по активностям MVP и пути эскалации — база для процессов, BRD и коммуникаций.

Стейкхолдеры ниже — **подразделения / функции**, не конкретные люди. Внешние — партнёрские организации (без привязки к брендам).

## 1. Карта стейкхолдеров

| Подразделение / стейкхолдер | Тип | Функция (роль в проекте) | Интерес | Влияние | Как вовлекаем |
|----------------------------|-----|--------------------------|---------|---------|---------------|
| Продуктовый отдел (бизнес-заказчик) | внутренний | владелец бизнес-результата: scope, приоритеты, приёмка KPI | конверсия, take-rate страховки, Time-to-Cash | высокое | заказчик продукта; freeze scope; UAT/go-live sign-off |
| Отдел кредитных рисков | внутренний | правила кредитного решения и контроль качества портфеля | approve/decline/manual review, proxy NPL | высокое | согласование правил решения и контрольных метрик риска |
| Комплаенс и юридический отдел | внутренний | регуляторная корректность согласий и отказных сценариев | согласия БКИ/ПДн, отказное решение, тексты оффера | высокое | раннее ревью согласий и отказов до freeze scope |
| Операционный отдел (ручной разбор заявок) | внутренний | бэк-офис выдачи: ручной разбор и исключения | нагрузка операторов, качество manual review | среднее | UAT сценариев manual review; фидбек по исключениям |
| IT-отдел (разработка и интеграции) | внутренний | поставка journey, интеграций и надёжности систем | БКИ, страховой API, АБС, канал заявки | высокое | проектирование и реализация интеграций и UI/API |
| Отдел QA (тестирование) | внутренний | проверка готовности к релизу | покрытие сценариев, регрессия, UAT | среднее | тест-план, критичные проверки, поддержка UAT |
| PM / BA (ведение проекта; совмещено с продуктом) | внутренний | ведение: требования, план, коммуникации | поставка в срок, прозрачность статуса | высокое | BRD/бэклог, RACI, статус-отчёты, change control |
| Страховой партнёр (внешний) | внешний | расчёт и оформление страхового оффера при выдаче | объём полисов, качество лидов | среднее | контракт и спецификация обмена; согласование полей и статусов |
| БКИ (внешний провайдер) | внешний | предоставление кредитной истории по контракту | SLA, форматы запрос/ответ | среднее | контракт и спецификация обмена; мониторинг SLA; эскалация инцидентов |

### Краткая карта интерес × влияние

| | Низкий интерес | Высокий интерес |
|--|----------------|-----------------|
| **Высокое влияние** | — | Продуктовый отдел, Отдел кредитных рисков, Комплаенс и юр. отдел, IT-отдел, PM/BA |
| **Среднее / низкое влияние** | БКИ (по контракту) | Операционный отдел, Отдел QA, Страховой партнёр |

БКИ и страховой партнёр — внешние: влияние через контракт и SLA, не через внутренний backlog.

## 2. Матрица RACI (MVP)

**Легенда:** R — Responsible (делает) · A — Accountable (один на строку, финально отвечает) · C — Consulted · I — Informed

Сокращения в шапке: Продукт = Продуктовый отдел · Кред. риски = Отдел кредитных рисков · Комплаенс = Комплаенс и юридический отдел · Операции = Операционный отдел (ручной разбор) · IT = IT-отдел · QA = Отдел QA · Партнёр = Страховой партнёр

| Активность MVP | Продукт | Кред. риски | Комплаенс | Операции | IT | QA | PM/BA | Партнёр | БКИ |
|----------------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| Scope MVP / freeze требований | A | C | C | I | C | I | R | I | I |
| BRD / user stories / DoR | C | C | C | C | C | C | A/R | I | I |
| Правила решения (approve / decline / manual review) | C | A | C | C | R | I | C | — | — |
| Согласия ПДн / БКИ, отказные тексты | C | I | A | I | R | I | C | — | — |
| Интеграция БКИ (контракт, таймауты, ретраи) | I | C | C | I | A/R | C | C | — | C |
| Интеграция страхового оффера | C | I | C | I | A/R | C | C | C | — |
| Интеграция с АБС / выдача | C | C | I | C | A/R | C | C | — | — |
| UI/API канала заявки (journey) | C | I | C | I | A/R | C | C | — | — |
| Мониторинг SLA и статусов интеграций | I | I | I | I | A/R | C | C | I | I |
| Тест-план и подготовка UAT | C | C | C | C | C | R | A | I | I |
| Проведение UAT / sign-off | A | C | C | R | C | C | R | I | I |
| Go-live MVP (решение о релизе) | A | C | C | I | C | C | R | I | I |
| Статус-отчёты / ритуал синхронизации | I | I | I | I | I | I | A/R | I | I |
| Change control (запрос вне scope) | A | C | C | I | C | I | R | I | I |

### Пояснения к спорным ячейкам

- **A/R у одной роли** — в совмещённой модели ведения A и R могут совпадать у PM/BA или IT; при разделении ролей в оргструктуре Accountable рекомендуется отделить от Responsible.
- **UAT sign-off:** Accountable — Продуктовый отдел; Операционный отдел — Responsible по сценариям manual review; PM/BA — Responsible за организацию прогона.
- **Правила решения:** Accountable — Отдел кредитных рисков; IT реализует; Продуктовый отдел консультирует по влиянию на конверсию.
- Внешние партнёры почти везде C/I: не владеют внутренним backlog, но консультируются по контракту и спецификации обмена.

## 3. Эскалации (при блокере)

| Тип блокера | Сначала | Если не снято |
|-------------|---------|----------------|
| Scope / приоритет / бизнес-KPI | PM/BA → Продуктовый отдел | Продуктовый отдел (финальное решение) |
| Правила approve/decline / риск-порог | PM/BA → Отдел кредитных рисков | Продуктовый отдел + Отдел кредитных рисков |
| Согласия, ПДн, отказные формулировки | PM/BA → Комплаенс и юридический отдел | Комплаенс (без OK — не freeze / не go-live) |
| Сбой или срыв SLA БКИ / страхового API | IT-отдел → партнёр по контракту | PM/BA на статус; Продуктовый отдел — fallback (manual review / отложить оффер) |
| Неготовность к UAT / критичные дефекты | Отдел QA + IT-отдел → PM/BA | Продуктовый отдел (сдвиг даты / сужение scope) |
| Конфликт «скорость vs compliance/риск» | PM/BA | Продуктовый отдел + Отдел кредитных рисков + Комплаенс на одном созвоне |

Принцип: один Accountable на решение; PM/BA фасилитирует, но не подменяет Отдел кредитных рисков и Комплаенс на их A-зонах.
