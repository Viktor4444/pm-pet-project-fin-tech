# План коммуникаций — Credit Journey MVP

**Версия:** 1.0  
**Дата:** 2026-11-09  
**Согласовано:** Продуктовый отдел (бизнес-заказчик) при участии IT-отдела, Отдела кредитных рисков, Комплаенс и юридического отдела, Операционного отдела и Отдела QA  
**Подготовил:** PM / BA  

**Опора:** [One-pager](../one-pager.md) §9, [Стейкхолдеры и RACI](../stakeholders-raci.md), [Реестр рисков](../risks/risk-register.md)  
**Фасилитатор:** PM / BA  
**Инструменты:** Confluence (документы), Jira (исполнение), статус-отчёт (короткий MD/Confluence page), MS Project (мастер-план — по необходимости)

## 1. Аудитории

| Аудитория | Зачем им информация |
|-----------|---------------------|
| Продуктовый отдел | scope, KPI, go/no-go |

## 2. Ритуалы и контрольные точки

| Событие | Когда | Формат / канал | Владелец (R) | Обязательные участники | Артефакт |
|---------|-------|----------------|--------------|------------------------|----------|
| Kick-off MVP | старт | встреча + Confluence | PM/BA | Product, Риски, Комплаенс, IT, QA, Операции | one-pager, RACI, BRD v1.0, эпики |
| Статус проекта | 1× в неделю | 15–30 мин sync + короткий статус | PM/BA | Product, IT (lead), QA; остальные — I / по запросу | статус: прогресс `CJ:` / E*, риски ≥6, BRD Pending input |
| Freeze scope MVP | до активной разработки «в ширь» | решение на sync / отдельный созвон | PM/BA | **A:** Product; C: Риски, Комплаенс, IT | зафиксированный scope + out of scope |
| Ревью согласий/текстов | до freeze / сразу после | async Confluence + созвон при споре | PM/BA | **A:** Комплаенс; C: Product | утверждённые тексты |
| Ревью правил решения | до/параллельно E3 | sync или async | PM/BA | **A:** Риски; C: Product, IT | конфиг правил + коды |
| Demo / показ инкремента | каждые 1–2 недели | демо | IT + PM/BA | Product; C: Риски/Операции по фиче | Jira done + заметки |
| UAT gate | перед go-live | прогон + sign-off | PM/BA + QA | **A:** Product; R: Операции (MR); C: Риски, Комплаенс, IT | чек-лист E8, дефекты |
| Go-live MVP | релиз | go/no-go | PM/BA | **A:** Product; C: Риски, Комплаенс, IT, QA | чеклист go-live |
| Ретро | после go-live | встреча | PM/BA | ядро команды | actions в Jira |
| Инцидент БКИ / страхование | по факту | чат/мост IT → статус если > SLA | IT | партнёр; Product если бизнес-impact | тикет + запись в мониторинге |

Частоту статуса можно сжать до 2×/нед. на критическом отрезке перед UAT — решение Product + PM/BA.

## 3. Еженедельный статус (шаблон)

Коротко, без простыней:

1. Прогресс по эпикам E1–E8 / Jira `CJ: …` (Done / In progress / Blocked)  
2. **BRD Pending input:** открытые Q1–Q7 и кто должен дать данные на этой неделе  
3. Риски с баллом ≥ 6: изменение / новый ([реестр](../risks/risk-register.md))  
4. Решения, нужные от Product / Рисков / Комплаенс на этой неделе  
5. План на следующий цикл  

Рассылка: Confluence/MD + ссылка в чат; Jira — source of truth по задачам.

## 5. Эскалации

Кратко (детали — [Стейкхолдеры и RACI](../stakeholders-raci.md) §3):

| Блокер | Путь |
|--------|------|
| Scope / KPI | PM/BA → Product |
| Правила / порог риска | PM/BA → Отдел кредитных рисков → (+ Product) |
| Согласия / ПДн | PM/BA → Комплаенс (без OK — не freeze/go-live) |
| SLA БКИ / страхование | IT → партнёр → PM/BA на статус → Product (fallback) |
| UAT / критичные дефекты | QA + IT → PM/BA → Product (дата/scope) |
| Скорость vs controls | совместный созвон Product + Риски + Комплаенс |

---

## 6. Чего не делаем

- Не тащим внешних партнёров на каждый weekly — только инциденты и согласованные контрактные изменения.
- Не дублируем Jira длинными письмами: статус = summary, детали в тикетах.
- Не подменяем A-зоны Рисков и Комплаенс «устным ок» Product без их фиксации.
