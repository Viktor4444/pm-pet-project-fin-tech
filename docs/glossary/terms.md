## Домен и продукт

| Термин | Определение |
|--------|-------------|
| <a id="abs"></a> **АБС** | Автоматизированная банковская (учётная) система — внутренний контур учёта заявок, решений и выдачи займа. |
| <a id="approve-decline"></a> **approve / decline** | Решения по заявке: одобрить / отказать. |
| <a id="bki"></a> **БКИ** | Бюро кредитных историй — внешний провайдер кредитной истории клиента по API. |
| <a id="ki"></a> **КИ** | Кредитная история — данные о обязательствах и платежной дисциплине клиента (источник — БКИ). |
| <a id="manual-review"></a> **manual review** | Ручной разбор заявки оператором, когда авто-правила не дают однозначного решения. |
| <a id="mfo"></a> **МФО / МКК** | Микрофинансовая / микрокредитная организация — тип кредитора в логике краткосрочных онлайн-займов. |
| <a id="npl"></a> **NPL** | Non-Performing Loan — просроченный / неработающий кредит; в кейсе — контрольная метрика качества риска (в т.ч. proxy / early delinquency). |
| <a id="offer"></a> **оффер** | Предложение клиенту условий займа или страховки (сумма, срок, полис и т.п.). |
| <a id="opt-in"></a> **opt-in** | Добровольное принятие оффера; отказ от страховки **не** блокирует выдачу займа. |
| <a id="pdn"></a> **ПДн** | Персональные данные; в кейсе — согласия на обработку ПДн и на запрос в БКИ. |
| <a id="take-rate"></a> **Take-rate** | Доля клиентов, принявших оффер (здесь — страховки при выдаче). |

## Процессы и требования

| Термин | Определение |
|--------|-------------|
| <a id="as-is"></a> **AS-IS** | Описание текущего («как есть») процесса. |
| <a id="brd"></a> **BRD** | Business Requirements Document — документ бизнес-требований. |
| <a id="journey"></a> **journey** | Сквозной путь клиента (и систем) от заявки до выдачи / отказа. |
| <a id="kpi"></a> **KPI** | Key Performance Indicator — ключевой показатель эффективности (например Time-to-Decision). |
| <a id="one-pager"></a> **one-pager** | Краткая одностраничная выжимка бизнес-кейса: проблема, цель, KPI, scope. |
| <a id="sla"></a> **SLA** | Service Level Agreement — договорённый уровень сервиса (например время ответа БКИ). |
| <a id="scope"></a> **scope / out of scope** | Границы проекта: что входит в поставку и что сознательно исключено. |
| <a id="tbd"></a> **TBD** | To Be Determined — значение будет определено позже (открытый вход, не выдуманная цифра). |
| <a id="time-to-cash"></a> **Time-to-Cash** | Время от одобрения займа до зачисления денег клиенту. |
| <a id="time-to-decision"></a> **Time-to-Decision** | Время от подачи заявки до решения approve / decline. |
| <a id="to-be"></a> **TO-BE** | Описание целевого («как будет») процесса / journey. |

## Управление проектом

| Термин | Определение |
|--------|-------------|
| <a id="backlog"></a> **backlog** | Упорядоченный список работ (эпики, stories), ожидающих выполнения. |
| <a id="dor-dod"></a> **DoR / DoD** | Definition of Ready / Definition of Done — критерии «можно брать в работу» и «считаем выполненным». |
| <a id="epic"></a> **epic (эпик)** | Крупный блок поставки в backlog; в кейсе эпики названы с префиксом `CJ: …`. |
| <a id="go-live"></a> **go-live** | Вывод решения в промышленную эксплуатацию (релиз «в бой»). |
| <a id="mirror"></a> **mirror (в git)** | Копия структуры задач/описаний из Jira (или аналога) в репозитории для портфолио и трассировки. |
| <a id="mvp"></a> **MVP** | Minimum Viable Product — минимальный ценный релиз (Release 1), достаточный для проверки гипотезы. |
| <a id="open-points"></a> **open points** | Управляемый список открытых вопросов / незакрытых входов (владельцы, влияние на план), без подстановки выдуманных цифр. |
| <a id="phase-2"></a> **Phase 2** | Второй релиз после MVP: расширение правил, отчётности, устойчивости интеграций. |
| <a id="raci"></a> **RACI** | Матрица ролей: Responsible / Accountable / Consulted / Informed. |
| <a id="stakeholder"></a> **стейкхолдер** | Заинтересованная сторона проекта (подразделение, внешний партнёр, роль с интересом к результату). |
| <a id="uat"></a> **UAT** | User Acceptance Testing — приёмочное тестирование бизнес-пользователями / заказчиком. |
| <a id="wbs"></a> **WBS** | Work Breakdown Structure — иерархическая декомпозиция работ проекта. |
