# One-pager: Credit Journey

**Версия:** 1.0  
**Дата:** 2026-11-09  
**Согласовано:** Продуктовый отдел (бизнес-заказчик)  
**Подготовил:** PM / BA  

**Проект:** онлайн-выдача займа + проверка БКИ + страхование в момент выдачи  
**Тип:** интеграционный / внедрение нового процесса  
**Горизонт:** 8–12 недель, 2 релиза (MVP → Phase 2)  
**Роли ведения:** Product + BA + PM (совмещённо)

---

## 1. Проблема

В текущем процессе выдачи займа проверка кредитной истории и предложение страхования разрознены или выполняются поздно. Это увеличивает Time-to-Decision и Time-to-Cash, снижает конверсию воронки и недобирает доход от страхового кросс-селла при приемлемом уровне риска.

## 2. Бизнес-цель

Сократить время от заявки до решения/выдачи и встроить проверку БКИ и оффер страхования в единый цифровой journey без роста просрочки сверх согласованного порога.

## 3. KPI

Направления метрик согласованы. Точные baseline и target фиксируются после предпроектного обследования (AS-IS).

| Метрика | Направление | Комментарий |
|---------|-------------|-------------|
| Time-to-Decision | ↓ | от подачи заявки до approve/decline |
| Time-to-Cash | ↓ | от approve до зачисления |
| Conversion Application → Offer | ↑ | доля дошедших до оффера |
| % отказов по БКИ / причинам | контролировать | прозрачная аналитика причин |
| Take-rate страховки при выдаче | ↑ | доля принявших оффер |
| SLA ответа БКИ | соблюдать | p95 времени ответа интеграции |
| Proxy NPL / early delinquency | не ухудшить | контрольная метрика риска |

## 4. Scope

### MVP (Release 1)

- Заявка на займ (цифровой канал)
- Согласие на запрос в БКИ и обработку ПДн
- Интеграция с БКИ: запрос → ответ → интерпретация для решения
- Решение: approve / decline / manual review
- Оффер страхования на шаге выдачи (opt-in: отказ от полиса не блокирует выдачу)
- Выдача (зачисление) при accept оффера займа
- Базовый мониторинг SLA и статусов интеграций
- UAT и чек-листы качества

### Phase 2 (Release 2)

- Расширенные правила скоринга / ручной разбор
- A/B офферов страхования
- Повторные запросы / кэш политики БКИ
- Расширенная отчётность для риска и продукта
- Обработка частичных сбоев и компенсирующие сценарии

### Out of scope

- Собственная ML-модель скоринга «с нуля»
- Мобильное приложение с нуля
- Полноценный коллекшен / реструктуризация
- Замена АБС целиком

## 5. Стейкхолдеры

Подразделения и функции. Детальная матрица RACI — в документе [Стейкхолдеры и RACI](stakeholders-raci.md).

| Подразделение / стейкхолдер | Интерес | Функция (роль в проекте) |
|----------------------------|---------|--------------------------|
| Продуктовый отдел (бизнес-заказчик) | конверсия, take-rate, TTC | владелец бизнес-результата и scope |
| Отдел кредитных рисков | качество портфеля, правила решения | правила approve/decline/manual review |
| Комплаенс и юридический отдел | согласия, ПДн, отказное решение | регуляторная корректность сценариев |
| Операционный отдел (ручной разбор заявок) | нагрузка и качество manual review | бэк-офис: ручной разбор и исключения |
| IT-отдел (разработка и интеграции) | БКИ, страховой API, надёжность | поставка journey и интеграций |

## 6. Ключевые интеграции

1. **БКИ** — запрос кредитной истории, коды ошибок, таймауты, ретраи  
2. **Страховой партнёр** — расчёт/оффер полиса, акцепт, статус оформления  
3. **Внутренняя система займов / АБС** — заявка, решение, выдача  
4. **Канал клиента** — UI/API фронта заявки (как потребитель процесса)

## 7. Ограничения и допущения

- Комплаенс-рамка проекта: согласия, отказные сценарии и обработка ПДн; детальная юрэкспертиза вне scope документа.
- Интеграции с БКИ и страховым партнёром ведутся по согласованным контрактам и спецификациям обмена.
- Состав команды: backend, frontend, QA, кредитные риски, комплаенс; ведение — совмещённый PM/BA/Product.
- Инструменты ведения: Confluence (документы), Jira (исполнение), MS Project (мастер-план).

## 8. Риски (топ)

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Нестабильный SLA БКИ | задержки решения, падение конверсии | таймауты, ретраи, fallback на manual review, мониторинг |
| Срыв согласования compliance | сдвиг релиза | раннее ревью согласий и отказных сценариев |
| Scope creep (скоринг/приложение) | срыв сроков MVP | жёсткий out of scope, change control |
| Низкий take-rate страховки | невыполнение бизнес-цели | тест оффера, момент показа, прозрачная ценность для клиента |
| Расхождение данных АБС ↔ партнёры | ошибки выдачи | контракт полей, идемпотентность, сверки |

## 9. Качество и контроль

- Definition of Ready / Definition of Done для требований и задач
- UAT по сценариям: approve, decline, timeout БКИ, отказ от страховки, сбой страхового API
- Контрольные точки: kick-off, freeze scope MVP, UAT gate, go-live MVP, ретро
