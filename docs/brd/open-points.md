# Open points — Credit Journey MVP

> Термин: [open points](../glossary/terms.md#open-points)

**Версия:** 1.0  
**Дата:** 2026-11-10  
**Владелец лога:** PM / BA  
**Опора:** [BRD](brd-credit-journey.md) §3 / §13, [реестр рисков](../risks/risk-register.md) (R09), [эпики](../backlog/jira-epics-mvp.md)

## 1. Назначение

Реестр открытых решений и входов со статусом «Ожидает данных». Здесь **не** подставляем выдуманные KPI/SLA/% MR — фиксируем вопрос, владельца ответа, влияние на поставку и статус.

Источник формулировок вопросов — [BRD §13](brd-credit-journey.md); этот файл — **ведение** (трассировка на план, эпики, риски).

## 2. Правила ведения

| Статус | Смысл |
|--------|--------|
| `open` | ответа ещё нет |
| `in progress` | владелец собирает данные / на согласовании |
| `answered` | ответ зафиксирован в BRD (или связанном артефакте); open point закрыт |
| `deferred` | сознательно отложено (с причиной и на какую фазу) |

- Лог обновляет **PM / BA**; ответы дают владельцы из колонки «Владелец ответа».  
- Эскалация: если open point блокирует [DoR](../glossary/terms.md#dor-dod) эпика или mid-MVP — в статус-отчёт и на риск [R09](../risks/risk-register.md).  
- Числовые `[TBD]` в BRD закрываем только после реального ответа владельца, не «для красоты».

## 3. Процесс работы (цикл)

1. **Обозначили** — вопрос попал в BRD и в этот лог (`open`).  
2. **Ведём** — без выдуманных цифр; видим влияние на эпики/риски.  
3. **Закрываем** — ответ → `answered` (+ правка BRD); привязку к вехам плана (колонка «Нужно к») закрываем отдельно, когда появится мастер-план в `docs/plan/` (задача MS Project).  
4. **Фиксируем** — строка в §7 «История» этого файла и/или итог соответствующей plan-задачи: было требование → сделали → закрыли.
